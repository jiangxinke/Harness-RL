# DCC experiment

## Model and held-out data

This run uses `Qwen/Qwen3-30B-A3B-Instruct-2507`, revision
`0d7cf23991f47feeb3a57ecb4c9cee8ea4a17bfe`. It is nominally a 30B model,
with **30.5B total parameters** and approximately 3.3B activated per token;
it exceeds a strict 30B total-parameter limit.

CUAD contains 15,908 training questions from 388 contracts, 820 validation
questions from 20 contracts, and the official test split of 4,182 questions
from 102 contracts. WideSearch is the official ByteDance-Seed benchmark:
all 200 tasks, comprising 100 English and 100 Chinese tasks, are held out.
No official WideSearch question or reference answer enters training.

## Training

The frozen BF16 base model is replicated across eight workers. Attention
`q_proj`, `v_proj`, and `o_proj` adapters use LoRA rank 8 and alpha 16;
expert weights remain frozen. Adapter gradients are averaged across workers.

| Setting | Initial run | Corrected-policy continuation |
| --- | ---: | ---: |
| SFT optimizer steps | 32 | 0 |
| RL optimizer steps | 24 | 8 |
| Samples per group per worker | 2 | 4 |
| Learning rate | 0.00002 | 0.000005 |
| SFT auxiliary coefficient | 0.1 | 0 |
| Maximum prompt tokens | 4,096 | 4,096 |
| Maximum completion tokens per turn | 512 | 512 |
| Maximum model turns | 3 | 3 |
| Initial retrieval chunks | 4 | 4 |
| Seed | 42 | 43 |

The initial run used temperature 0.8, top-p 0.95, and top-k 20 while scoring
raw model log probabilities. The continuation corrects that discrepancy with
temperature 1, top-p 1, top-k 0, and no inherited sampling penalties or filters.
It warm-starts the initial adapter with a fresh optimizer and RNG state.
Both phases contribute to the final weights; the initial discrepancy is not
retroactively removed. See [dcc_training.md](dcc_training.md) for the loss
definition and limitations of the single-update group-relative objective.

The corrected continuation produced 256 trajectories: 248 completed and eight
exhausted their turn budget, with zero infrastructure failures. Fifteen of 64
groups had nonzero reward variance; five of eight optimizer steps had nonzero
global gradients. The run used no SFT auxiliary, establishing actual RL
optimization signal. Exact trajectories and per-worker diagnostics are retained
with the external checkpoints. A direct comparison of the saved adapters found
that all 288 tensors (5,701,632 trainable parameters) changed during the
continuation; all final weights are finite. The weight-change L2 norm is 0.034580.

## Validation selection

The checkpoint was selected using a seed-42 sample of 82 validation questions
covering all 20 validation contracts, before inspecting test scores. Base and
trained models use the same corrected harness, greedy decoding, 8,192 prompt
tokens, 1,024 completion tokens per turn, at most three turns, and four initial
retrieval chunks. Both completed all 82 questions with no infrastructure errors.

| Validation metric | Frozen base | Selected adapter |
| --- | ---: | ---: |
| AUPR | 0.090109 | 0.182757 |
| Micro precision | 0.206897 | 0.473684 |
| Micro recall | 0.300000 | 0.300000 |
| Micro F1 | 0.244898 | 0.367347 |
| Precision at 80% / 90% recall | 0 / 0 | 0 / 0 |

These are validation results, not full test scores. The selected policy
answered all 82 questions from initial retrieval in one turn; it made no
additional document tool calls. This short run improves precision but does not
establish improved retrieval or recall. Span confidence is generated by the
model and has not been calibrated.

## Test protocol and status

Full test evaluation is in progress. Final results will be added after full
coverage, infrastructure checks, and judge validation finish.

CUAD uses the official word-set Jaccard threshold of 0.5, with the official
Parties substring exception. Reports include AUPR, precision at 80% and 90%
recall, and additional micro precision, recall, and F1. Correctly predicting an
empty answer earns training reward but does not create an official true positive.

WideSearch uses 12 model turns, 16,384 prompt tokens, and 8,192 completion
tokens per turn. The default `public_web` provider tries DuckDuckGo, Seznam
for non-Chinese queries, Baidu mobile, and Wikipedia; actual backend coverage
is recorded with predictions. An independent English/Chinese tool preflight
must pass before running the held-out tasks.

The WideSearch report will include a deterministic strict proxy and the official
metric pipeline with a **custom frozen base-Qwen judge**. This is not the
published GPT-4.1 leaderboard judge or a directly comparable leaderboard score.
All 200 tasks remain in the denominator. Infrastructure and judge failures are
reported explicitly; successful subsets are never presented as a full run.

## Reproduction and artifacts

See [dcc.md](dcc.md) and [dcc_training.md](dcc_training.md) for portable
installation, preparation, training, scoring, and resume commands. Configure
model, data, and output roots through CLI arguments or environment variables.
Runtime paths, credentials, model weights, logs, and predictions are excluded
from the repository.

Within the configured artifact root, the selected adapter is
`dcc-run/training-raw/final`; the initial adapter is `dcc-run/training/final`.
Validation predictions are in `dcc-run/dev82-v2-baseline` and
`dcc-run/dev82-v2-trained`. Planned full-test outputs are `dcc-run/cuad-final`
and `dcc-run/widesearch-final`.

The code revision preceding this report passed 322 CPU regression checks with
one optional real-tokenizer check skipped. This includes real tiny-Qwen3MoE
generation/log-probability parity checks and retained Harness-RL/OLE tests.
