# DCC experiment

## Model and held-out data

This run uses `Qwen/Qwen3-30B-A3B-Instruct-2507`, revision
`0d7cf23991f47feeb3a57ecb4c9cee8ea4a17bfe`. It is nominally a 30B model,
with **30.5B total parameters** and approximately 3.3B activated per token;
it exceeds a strict 30B total-parameter limit.

CUAD contains 15,908 training questions from 388 contracts, 820 validation
questions from 20 contracts, and the official test split of 4,182 questions
from 102 contracts. WideSearch is the official ByteDance-Seed benchmark:
all 200 tasks, comprising 100 English and 100 Chinese tasks, are held out.
No official WideSearch question or reference answer enters training.

Data versions are pinned: CUAD is from `The-Atticus-Project/cuad` at Git
revision `67faa0e6023b04fcaae6cc09497ab00e5d63a2a2`; WideSearch uses Hugging
Face dataset `ByteDance-Seed/WideSearch` revision
`6531a7e5b497d44c8912407e0cb3dc95bd98cc09`. The reference WideSearch evaluator
is Git revision `9825ba7b140b71d81b364793f86dabe4cfed6749` of the same project.

## Training

The frozen BF16 base model is replicated across eight workers. Attention
`q_proj`, `v_proj`, and `o_proj` adapters use LoRA rank 8 and alpha 16;
expert weights remain frozen. Adapter gradients are averaged across workers.

| Setting | Initial run | Corrected-policy continuation |
| --- | ---: | ---: |
| SFT optimizer steps | 32 | 0 |
| RL optimizer steps | 24 | 8 |
| Samples per group per worker | 2 | 4 |
| Learning rate | 0.00002 | 0.000005 |
| SFT auxiliary coefficient | 0.1 | 0 |
| Maximum prompt tokens | 4,096 | 4,096 |
| Maximum completion tokens per turn | 512 | 512 |
| Maximum model turns | 3 | 3 |
| Initial retrieval chunks | 4 | 4 |
| Seed | 42 | 43 |

The initial run used temperature 0.8, top-p 0.95, and top-k 20 while scoring
raw model log probabilities. The continuation corrects that discrepancy with
temperature 1, top-p 1, top-k 0, and no inherited sampling penalties or filters.
It warm-starts the initial adapter with a fresh optimizer and RNG state.
Both phases contribute to the final weights; the initial discrepancy is not
retroactively removed. See [dcc_training.md](dcc_training.md) for the loss
definition and limitations of the single-update group-relative objective.

The corrected continuation produced 256 trajectories: 248 completed and eight
exhausted their turn budget, with zero infrastructure failures. Fifteen of 64
groups had nonzero reward variance; five of eight optimizer steps had nonzero
global gradients. The run used no SFT auxiliary, establishing actual RL
optimization signal. Exact trajectories and per-worker diagnostics are retained
with the external checkpoints. A direct comparison of the saved adapters found
that all 288 tensors (5,701,632 trainable parameters) changed during the
continuation; all final weights are finite. The weight-change L2 norm is 0.034580.

## Validation selection

The checkpoint was selected using a seed-42 sample of 82 validation questions
covering all 20 validation contracts, before inspecting test scores. Base and
trained models use the same corrected harness, greedy decoding, 8,192 prompt
tokens, 1,024 completion tokens per turn, at most three turns, and four initial
retrieval chunks. Both completed all 82 questions with no infrastructure errors.

| Validation metric | Frozen base | Selected adapter |
| --- | ---: | ---: |
| AUPR | 0.090109 | 0.182757 |
| Micro precision | 0.206897 | 0.473684 |
| Micro recall | 0.300000 | 0.300000 |
| Micro F1 | 0.244898 | 0.367347 |
| Precision at 80% / 90% recall | 0 / 0 | 0 / 0 |

These are validation results, not full test scores. The selected policy
answered all 82 questions from initial retrieval in one turn; it made no
additional document tool calls. This short run improves precision but does not
establish improved retrieval or recall. Span confidence is generated by the
model and has not been calibrated.

results will be added after full coverage and judge validation finish.

| AUPR | 0.182906 |
| Micro precision | 0.457637 |
| Micro recall | 0.310632 |

There were 4,180 completed episodes and two exhausted turn budgets, with zero
infrastructure failures. All 4,182 questions remain in the denominator. Model
generation took approximately 2,033 seconds across eight workers, excluding
model initialization. The full-test recall and zero high-recall precision show
that this short training run still has substantial extraction and retrieval
limitations; no convergence or leaderboard-quality claim is made.
The run used 6,815,159 prompt and 178,444 completion tokens. It made no
additional document-tool calls: all answers relied on initial retrieval.

CUAD uses the official word-set Jaccard threshold of 0.5, with the official
Parties substring exception. Reports include AUPR, precision at 80% and 90%
recall, and additional micro precision, recall, and F1. Correctly predicting an
empty answer earns training reward but does not create an official true positive.

WideSearch uses 12 model turns, 16,384 prompt tokens, and 8,192 completion
tokens per turn, with one active generation request per worker. An initial
four-request batch exceeded memory during MoE prefill before any prediction
was saved. The run resumed at batch size one with unchanged model, adapter,
seed, and per-task budgets; that runtime failure contributes no model zeros.
The default `public_web` provider tries DuckDuckGo, Seznam
for non-Chinese queries, Baidu mobile, and Wikipedia; actual backend coverage
is recorded with predictions. An independent English/Chinese tool preflight
must pass before running the held-out tasks.

An initial independent preflight exposed premature final answers without any
search or page read, including unsupported URLs. The WideSearch-only
`search-fetch-citations-ndjson-v2` guard requires a successful search with source
URLs and a successful nonempty page read before accepting a final answer.
Every returned row must cite an observed source URL. Rejected finals receive
explicit corrective feedback within the original turn budget; exhausted guards
are model failures scored as zero, not infrastructure exclusions. CUAD behavior
is unchanged. A fresh output directory and manifest version prevent mixing
these predictions with the initial failed preflight.
The guard also accepts a complete terminal payload containing one JSON answer
row per line, with or without a single surrounding JSON code fence. Mixed tool
actions, incomplete rows, or surrounding prose do not trigger this fallback.
The normal answer schema and citation checks still apply.

Short-budget independent preflights completed six of eight tasks at four and
six turns, exposing recoverable answer-format and blocked-page failures. At
the fixed 12-turn benchmark budget, all eight independent English/Chinese
tasks completed with successful searches, page reads, and valid citations,
with zero infrastructure failures. The final versioned NDJSON preflight also
completed all eight tasks with valid evidence and citations, zero infrastructure
failures, and the same 12-turn budget. It used 191,767 prompt tokens and 3,532
completion tokens. Preflight tasks are not drawn from the official benchmark.

The WideSearch report will include a deterministic strict proxy and the official
metric pipeline with a **custom frozen base-Qwen judge**. This is not the
published GPT-4.1 leaderboard judge or a directly comparable leaderboard score.
All 200 tasks remain in the denominator. Infrastructure and judge failures are
reported explicitly; successful subsets are never presented as a full run.

## Further optimization under validation

A separate full-expert NF4 runtime reduces frozen base-weight memory while
retaining attention LoRA training. Real-model checks covered all 18,432 expert
matrices, representing 100% of expert parameters. Loaded CUDA allocation was
16.79 GiB; complete 4,096-token and 16,384-token prefill plus 16 generated tokens
peaked at 17.89 and 21.17 GiB, respectively. A synthetic LoRA optimizer step
produced finite, nonzero gradients and saved an adapter. These are memory and
execution checks, not new benchmark scores. The separate quantized environment
uses unfused expert linear modules; enabling a generic four-bit switch on the
default fused implementation would leave the expert parameters unquantized.

Train-only CUAD query expansion raises full-span visibility in the 820-question
validation split from 307/621 to 411/621 while retaining four retrieved chunks
and approximately the same source-text budget. This is retrieval coverage, not
answer F1. The validation questions share the same 20 validation contracts;
subsampling questions does not create a new contract-level holdout.

An independent web curriculum has 58 bilingual training tasks from three IANA
registries and eight validation tasks from two different registries. All 58
teacher episodes completed actual search/read/cite checks and scored exactly
one against their public-source labels, yielding 174 supervised assistant
segments with zero failed teachers. No official WideSearch task or reference
enters this curriculum. See [dcc_web_curriculum.md](dcc_web_curriculum.md).
The first mixed-training candidate has finished; policy validation remains in
progress. The full-test scores above continue to identify the original selected
adapter, rather than a new candidate.

Grounded CUAD tool teachers add 128 training episodes from 38 clause categories,
yielding 384 search/read/final segments. All 558 web and CUAD teacher segments
passed source and encoded-context checks with no skipped tool records. Queries
use public question/profile terms; document reads start at actual search hits.
Training labels select successful teaching plans but never enter evaluation
prompts or select evaluation sources.

Matched two-step mixed LoRA trials completed with finite, nonzero gradients and
saved adapters in both runtimes. NF4 took 86.51 and 85.75 seconds per step;
BF16 took 4.97 and 4.63 seconds, with a measured 58.52 GiB allocation peak.
The 24-step BF16 candidate completed with checkpoints at steps 12 and 24.
Every loss and gradient norm was finite and nonzero. It trained on 93 selected
examples from 78 distinct tasks: 44 web segments, 26 CUAD tool segments,
21 direct negative answers and only two direct positive answers. Three dynamic
CUAD candidates were skipped for grounding or response-length limits. The
558 eligible teacher segments are a dataset size, not a claim that all were
used. Training took 255.6 seconds including setup, with a mean optimizer-step
time of 4.68 seconds and a 60.17 GiB allocation peak. All 288 adapter tensors
changed and remained finite. NF4 remains available when frozen weights do not
fit. Runtime checks alone do not establish task quality.

Matched single-worker BF16 validation of the original adapter completed all
82 questions with no infrastructure failures. Enabling the training-only
retrieval profile raised micro F1 from 0.340426 to 0.433333 and AUPR from
0.167424 to 0.258015. These comparisons use the same adapter, task IDs,
decoding budgets and worker configuration. The earlier eight-worker validation
above has different batch composition; its score must not be substituted for
this matched baseline. Checkpoint selection and further training remain in
progress. The small number of direct positive examples and lack of negative
tool trajectories motivate the next training mixture; official test answers
are not used to choose that mixture.

The first candidate's step-12 checkpoint gave micro F1 0.389381 and AUPR
0.200566 on those matched HF validation tasks; step 24 improved to 0.467290
and 0.267751, with precision 0.531915 and recall 0.416667. All 82 episodes
completed without infrastructure failures. The next training phase therefore
warm-starts step 24 with a fresh optimizer. Its configured mixture uses 25%
web examples, 30% CUAD tool examples within the CUAD portion, and a 25%
negative-answer target within CUAD. It completed 64 optimizer steps with eight
workers, four examples per worker, a 32,768-token per-step sampling budget,
learning rate 0.000005 and checkpoints every 16 steps. Its 2,048 actual examples
cover 1,305 distinct task IDs: 885 direct CUAD positives, 484 direct negatives,
502 web segments (167 search, 168 fetch, 167 final), and 177 CUAD tool segments
(58 search, 59 read, 60 final). Dynamic CUAD preparation skipped 486 candidates
that failed grounding or response-length checks. All 512 per-worker step
records have finite loss and nonzero finite gradient norms; workers agree on
the synchronized norms. All 288 adapter tensors changed from the warm start
and remain finite in each saved checkpoint. Training logs record 748.88 seconds;
checkpoint selection is still in progress on validation data only.

The next teacher set adds 48 training-only negative search/read/final episodes
from 40 categories. Merging the original 128 positive episodes gives 176
episodes and 528 CUAD segments covering all 41 categories. All segments pass
actual source replay and real-tokenizer budgets without skips; every one of
the eight training shards retains all three stages for both answer polarities.
The original positive records are retained byte-for-byte.

An optional vLLM graph runtime loaded the real attention adapter and completed
generation and engine shutdown. With the same adapter and exact 16,384-token
synthetic prompt, 128-token generation took 3.14 seconds versus 11.97 seconds
for HF; compilation and loading are excluded from those generation times.
Eager vLLM did not improve single-request throughput, so that mode was not
selected for speed. Matched 82-question validation with the retrieval profile
completed with zero infrastructure failures: graph vLLM micro F1 was 0.424779
and AUPR 0.243268, versus HF's 0.433333 and 0.258015. Generation took 52.45
seconds versus approximately 390 seconds. Fused kernels and BF16 LoRA
computation can change greedy answers; subsequent selection uses a single
runtime rather than substituting the higher score from another backend.

An additional CPU check of the complete 820-question validation split compares
four and eight initial retrieved chunks. Requiring a whole reference span to
occur inside one original, unnormalized chunk gives coverage of 407/621 and
481/621 spans, respectively. Median prompt lengths are 1,676.5 and 3,026 tokens;
the longest eight-chunk prompt is 4,008 tokens, below the 8,192-token budget.
This is a stricter visibility definition than normalized or combined-excerpt
checks. It motivates a harness candidate, not an answer-quality claim.

## Reproduction and artifacts

See [dcc.md](dcc.md) and [dcc_training.md](dcc_training.md) for portable
installation, preparation, training, scoring, and resume commands. Configure
model, data, and output roots through CLI arguments or environment variables.
Runtime paths, credentials, model weights, logs, and predictions are excluded
from the repository.

Within the configured artifact root, the selected adapter is
`dcc-run/training-raw/final`; the initial adapter is `dcc-run/training/final`.
Validation predictions are in `dcc-run/dev82-v2-baseline` and
`dcc-run/dev82-v2-trained`. Full CUAD outputs are in `dcc-run/cuad-final`;
full WideSearch outputs will be in `dcc-run/widesearch-final`.

The `45a0857f` checkpoint passed 494 CPU regression checks with two optional
checks skipped: the default CPU environment lacks bitsandbytes, and the
optional external SP tokenizer fixture was not configured. Those missing checks
were subsequently run separately: three NF4 checks and one real-Qwen tokenizer
check passed. Independent vLLM logical sharding at `6db35768` passed 60 targeted
CPU checks. BF16 and NF4 dependency/tool preflights both passed. This includes
real tiny-Qwen3MoE generation/log-probability parity checks and retained
Harness-RL/OLE tests. Later changes receive targeted checks recorded alongside
their implementation.
